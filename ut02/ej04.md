
# Ej04 - Cierre de la unidad: los pedidos

## 1. Validaciones en Java y en la base de datos

La base de datos utiliza restricciones como CHECK, UNIQUE y FOREIGN KEY para impedir que se guarden datos incorrectos.
Java también puede validar los datos antes de enviarlos.
Lo mejor es utilizar ambas: Java permite mostrar errores claros y la base de datos garantiza la integridad.

## 2. Seguridad de PreparedStatement

PreparedStatement utiliza parámetros (?) para evitar la inyección SQL.
Los datos introducidos por el usuario no se interpretan como instrucciones SQL.
Sin embargo, no evita otros problemas de seguridad, como accesos no autorizados o contraseñas mal protegidas.

## 3. Transacciones y atomicidad

Una transacción permite realizar varias operaciones como una sola unidad.
Si intentamos insertar un pedido con un producto inexistente, se produce un error y se ejecuta rollback().
Así no se guarda ni el pedido ni sus líneas. Esto demuestra la atomicidad: o se guarda todo o no se guarda nada.

## 4. Conexiones a la base de datos

En este ejercicio abrimos una conexión nueva en cada método.
Esto es sencillo, pero puede resultar lento si hay muchos usuarios.
En aplicaciones reales se utiliza un pool de conexiones para reutilizarlas y mejorar el rendimiento.
